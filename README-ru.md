# Continuum 🔄

### ИИ-агенты пишут код, который работает сегодня и ломается завтра. Continuum чинит его навсегда.

[![npm](https://img.shields.io/npm/v/continuum-runtime)](https://www.npmjs.com/package/continuum-runtime)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

---

**Continuum** — детерминированный рантайм для кода, сгенерированного ИИ. Он фиксирует что именно ИИ решил сделать, выполняет это в изолированном sandbox, и **доказывает** воспроизводимость результата — или **чинит его**, когда реальность изменилась.

Это **CI/CD для эпохи ИИ**: не просто "тесты прошли?", а "можем ли мы воспроизвести то, что ИИ построил, и починить, когда мир изменился?"

```bash
npm install -g continuum-runtime
```

## Проблема

Каждый день миллионы разработчиков используют ИИ для генерации кода. Каждую неделю этот код ломается:

- `express` обновляется с `4.21.2` до `4.21.3`
- Node обновляется с `20.11` до `20.12`
- Lockfile уезжает
- Модель ИИ меняет поведение

Ответ индустрии: *"Просто запусти ИИ заново."*
Это стоит денег, занимает время и даёт другой результат.

**Ответ Continuum:** Запусти один раз. Закэшируй план. Воспроизводи вечно. Чини когда нужно.

## Демо за 30 секунд

```bash
# 1. ИИ пишет код (единственный раз, когда ты платишь за LLM)
$ continuum run "Express API: GET /health, POST /echo, jest тесты, зафиксированные версии"
  ✓ Спланировано 6 шагов через Claude
  ✓ Выполнено в sandbox
  ✓ Проверки: 3/3 пройдены
  → Run ID: abc-123

# 2. Тот же промпт — ноль затрат на ИИ
$ continuum run "Express API: GET /health, POST /echo, jest тесты, зафиксированные версии"
  ✓ Plan cache hit — LLM не вызван
  ✓ Выполнено за 12с
  → Run ID: def-456

# 3. Докажи идентичность
$ continuum replay abc-123
  ✓ 6/6 хэшей артефактов совпали
  ✓ 3/3 проверки пройдены
  → REPLAY VERIFIED

# 4. Через месяц — зависимости уехали
$ continuum replay abc-123
  ✗ Обнаружен дрейф: express 4.21.2 → 4.21.3
  ✗ Проверка упала: GET /health → 500

# 5. Одна команда — всё починено
$ continuum replay abc-123 --heal
  ⚙ Level 1: Повтор нестабильных проверок... пропущен
  ⚙ Level 2: npm ci (детерминированный фикс)... применён
  ⚙ Повторная верификация... 3/3 проверки пройдены
  ✓ HEALED — generation 1 сохранён (ноль затрат на LLM)
```

Во время лечения ИИ не вызывался. Фикс был механическим.
LLM вызывается только в **крайнем случае** — когда детерминированные ремонты не помогли.

## Как это работает

```
Ты: "собери Express API с авторизацией"
         │
         ▼
    ┌─────────┐     в кэше?        ┌──────────┐
    │ Planner │────── да ──────────▶│ Кэш плана│
    │ (LLM)   │                    └─────┬─────┘
    └────┬────┘                          │
         │ нет                           ▼
         ▼                         ┌───────────┐
    ┌─────────┐                    │ Выполнение│
    │ Новый   │───────────────────▶│ (sandbox) │
    │  план   │                    └─────┬─────┘
    └─────────┘                          │
                                         ▼
                                  ┌──────────────┐
                                  │  Верификация  │
                                  │ хэши + assert│
                                  └──────┬───────┘
                                         │
                              ┌──────────┴──────────┐
                              │                     │
                         ✓ Verified            ✗ Дрейф
                              │                     │
                         Готово               Repair Cascade
                                                    │
                                          L1: Повтор (нестабильные)
                                          L2: Детерминированный фикс
                                          L3: LLM-ремонт (1 попытка)
                                          L4: Ручной (с диагностикой)
```

Каждый файл получает хэш `sha256`. Код возврата каждой команды записывается. Сам план хэшируется. **Replay сравнивает артефакты, а не stdout** — npm-варнинги не ломают билды.

## Верификация: два независимых слоя

| | Хэши совпали | Хэши разошлись |
|---|---|---|
| **Проверки прошли** | `identical` ✓ | `benign_drift` — принять новую реальность |
| **Проверки упали** | `regression` — баг в плане | `drifted` — запуск Repair Cascade |

**Benign drift** — ключевой инсайт: если `package-lock.json` изменился, но все тесты проходят — это не ошибка, это мир двигается вперёд. Continuum принимает это и создаёт новое поколение плана. Без LLM.

## Repair Cascade

Когда проверки падают, Continuum не бежит сразу к ИИ. Сначала — самый дешёвый фикс:

| Уровень | Что | Стоимость | Пример |
|---------|-----|-----------|--------|
| **1** | Повтор | $0 | Нестабильный HTTP-ассерт → подождать и повторить |
| **2** | Детерминированный фикс | $0 | Дрейф зависимостей → `npm ci` из lockfile |
| **3** | LLM-ремонт | ~$0.03 | Сломанный import → ИИ патчит один файл |
| **4** | Нереparable | $0 | Мажорная версия Node → говорит что именно делать |

**LLM вызывается примерно в 1 из 10 случаев.** Остальное — механика.

## CLI

| Команда | Что делает | LLM? |
|---------|-----------|------|
| `continuum run <prompt>` | Планирование + выполнение + верификация | Да (или кэш) |
| `continuum execute <plan.json>` | Выполнить любой план без LLM | **Нет** |
| `continuum replay <run_id>` | Повторить + проверить хэши | **Нет** |
| `continuum replay <id> --heal` | Обнаружить дрейф + Repair Cascade | Редко |
| `continuum explain <run_id>` | Человекочитаемый разбор по шагам | **Нет** |
| `continuum inspect <run_id>` | Полные данные (`--json`) | **Нет** |
| `continuum diff <id1> <id2>` | Сравнить хэши артефактов | **Нет** |
| `continuum history <plan_hash>` | Показать цепочку поколений | **Нет** |
| `continuum list` | Список всех запусков | **Нет** |
| `continuum freeze` | Зафиксировать версии окружения | **Нет** |

**8 из 10 команд никогда не обращаются к LLM.** Рантайм — это продукт, а не ИИ.

## План = исполняемый артефакт

Планы — это JSON. Их может написать ИИ, человек руками, или экспортировать из любого запуска:

```bash
# Экспортировать план из предыдущего запуска
continuum inspect abc-123 --json | jq '.plan' > my-api.plan.json

# Кто угодно может его выполнить — API-ключ не нужен
continuum execute my-api.plan.json

# Тот же результат. Каждый раз.
```

Планы хранят свою **родословную** — каждый ремонт создаёт новое поколение с полной историей:

```bash
$ continuum history sha256:aaa
  gen 0: sha256:aaa (оригинал, claude-sonnet, 15 янв)
    └─ gen 1: sha256:bbb (детерминированный: npm-ci, 25 фев)
        └─ gen 2: sha256:ccc (llm-ремонт: 1 мутация, 15 мар)
```

## Когда использовать Continuum

| Сценарий | Без Continuum | С Continuum |
|----------|--------------|-------------|
| ИИ-проект сломался через месяц | Запустить ИИ заново ($) | `replay --heal`, починено за секунды |
| Коллеге нужен тот же сетап | "Попроси ИИ ещё раз" | `continuum execute plan.json` |
| CI для ИИ-кода | Тесты проходят сегодня, завтра загадка | Детерминированный replay + проверки |
| Аудит решений ИИ | Логи чата (бесполезно) | Хэшированный план + цепочка поколений |
| Воспроизводимые эксперименты | "У меня работало" | Replay с fingerprint окружения |

## Требования

- **Node.js** ≥ 20
- **Docker** (для изоляции в sandbox)
- **Anthropic API key** (только для `continuum run` — всё остальное локальное)

## Философия (для любопытных)

<details>
<summary>Почему "рантайм", а не "агентский фреймворк"?</summary>

Все AI-инструменты сегодня фокусируются на том, чтобы сделать агентов умнее. Continuum фокусируется на том, чтобы сделать **результаты стабильными**.

LLM — это **компилятор**: вызывается один раз для создания плана, потом больше не нужен. Выполнение детерминировано. Верификация криптографическая. Ремонт сначала механический, потом интеллектуальный.

Это недостающий слой между "ИИ написал код" и "код в продакшне":

```
Git       → что изменилось
Docker    → где запускается  
CI/CD     → когда запускается
Continuum → ЗАЧЕМ это было создано и ДОКАЗАТЕЛЬСТВО что оно работает
```

</details>
